# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A single-file, zero-build Markdown viewer that renders ```` ```mermaid ```` blocks as zoomable/pannable diagrams. Everything (CSS, HTML, JS) lives in `Markdown_Mermaid_Viewer.html`. There is no package manager, build step, linter, or test suite — open the file in a browser to run it.

External dependencies are loaded from cdnjs: `marked` 9.1.6 (markdown → HTML) and `mermaid` 10.6.1 (diagrams); fonts from Google Fonts (Source Serif 4, JetBrains Mono).

## Checking changes

- Syntax-check the inline script: extract the contents of the `<script>` block (the one without `src`) to a `.js` file and run `node --check` on it.
- Visual check with headless Chrome (`C:/Program Files/Google/Chrome/Application/chrome.exe`): `--headless=new --window-size=W,H --virtual-time-budget=8000 --screenshot=out.png file:///path/test.html`. Use a copy of the page with a trailing script that clicks `#emptyExampleBtn` (or fills `#pasteTextarea` + clicks `#pasteRender`) so there is content. `--dump-dom` plus writing values into a `data-*` attribute is a handy way to read runtime state.
- Headless caveats: minimum window width is ~504px (a 400px window is not a real mobile viewport); `scrollTo` does not reliably fire `scroll` events and `requestAnimationFrame` may not run under virtual time — dispatch `new Event('scroll')` manually when testing scroll logic. Fullscreen API cannot be exercised headlessly.

## Architecture (inline script, one IIFE)

- **Rendering pipeline** — `renderMarkdown(text, filename, skipHistory)` resets diagram state, runs `marked.parse` with a custom `renderer.code` that swaps mermaid blocks for `.mermaid-wrap[data-id]` placeholders (source stored in `pendingDiagrams`), then calls `buildToc()`, then — after `document.fonts.ready`, so mermaid measures labels with the real font — calls `renderDiagram` per placeholder. `lastMarkdown` is kept so a theme switch can re-render everything. It also sets `document.title` to the file's base name (the `<title>` "Markdown Viewer" shows only before a document is loaded).
- **Diagram state** — `diagramStates[id]` holds `{scale, x, y, baseScale, svgW, svgH, cardEl, viewportEl, canvasEl, ...}`. The SVG is pinned to its viewBox pixel size; the canvas is positioned with a CSS `translate() scale()` transform (`applyTransform`). The zoom label shows `scale / baseScale`, so "100%" means "fitted".
- **Fitting** — `fitDiagram(id)`: inline, the diagram fits the card width (upscale capped by `MAX_UPSCALE`) and the viewport height is set to the diagram's height (capped at 85vh); in fullscreen it fits both dimensions. Refit happens on resize (only if width changed), fullscreen change, and TOC sidebar toggle.
- **Fullscreen** — ⤢ uses the native Fullscreen API on the `.diagram-card` (with webkit prefixes); if unavailable it falls back to a `.pseudo-fs` fixed-position class (`enterPseudoFullscreen` / `exitPseudoFullscreen`). ⧉ (left of ⤢) opens a popup instead: the card gets a `.popup` class (fixed, centered, over `#popupBackdrop`) and its wrapper keeps a `min-height` so the page doesn't jump; `togglePopup` / `closePopup`, closed by ✕, backdrop click, Esc, or any re-render. `isExpanded(st)` covers fullscreen, pseudo-fullscreen and popup.
- **Zoom/pan input** — inline, plain wheel scrolls the page; ctrl/⌘+wheel (and trackpad pinch) zooms. In fullscreen plain wheel zooms. Drag pans via pointer events with pointer capture.
- **TOC** — `buildToc()` slugifies h1–h4 into unique ids and fills `nav#toc` (shown only with ≥2 headings, via `body.has-toc`). A document with exactly one h1 treats it as the title and leaves it out (levels are renumbered from the shallowest remaining heading). ≥1100px it's a fixed left sidebar (`body.toc-collapsed` hides it and removes `main`'s left padding); below that it's a drawer (`body.toc-open`). Links jump instantly (`scrollIntoView` with `behavior: "instant"`). Active item tracked by `updateActiveToc()` on scroll (inside a collapsed group the collapsed ancestor is highlighted). The list stays flat (`li.lvl-N`); items followed by a deeper heading get a `.toc-caret` button, and the header's `.toc-all` button toggles collapse all / expand all. Collapsed groups live in `tocCollapsed` (keyed by heading slug, kept while the same filename is re-rendered — theme switch, reload) and `applyTocCollapse()` hides descendants with `.toc-hidden`.
- **Top bar** — sticky; the scroll handler toggles `body.bar-hidden` (hide on scroll down, show on scroll up / near top). `--bar-h` (set by `syncBarHeight`) positions the TOC below the bar. `body` must use `min-height` only, never `height: 100%` — otherwise the sticky header's containing block ends after one screen and the bar scrolls away.
- **Content width** — `#content` is capped at 700px; the ↔ button (`#widthBtn`, `aria-pressed`) toggles `body.full-width` (no cap) via `applyFullWidth`, stored in `localStorage["md-viewer-full-width"]`, and refits all diagrams.
- **Theme** — light by default (`<html data-theme="light">`, then `localStorage["md-viewer-theme"]`). Colors are CSS custom properties on `:root`, overridden under `[data-theme="dark"]`. `applyTheme` re-initializes mermaid (`default`/`dark` theme) and re-renders the document.
- **Input** — the top bar has one split button (`#openSplit`): the main part (`#openFolderBtn`) opens a folder, the ▾ caret (`#openMenuBtn`) opens `#openMenu` with open folder / open file (`#openBtn`) / paste text (`#pasteBtn`); `closeOpenMenu()` on item click, outside click, Esc, or opening the recent menu. Also drag-and-drop a file or folder anywhere (`#dropOverlay`), or the paste panel. A built-in example document is in `EXAMPLE_MD`. Opening a single file, pasting, or loading the example calls `clearFolder()`.
- **Links & folder mode** — browsers never expose a file's directory, so relative links can only resolve when a whole folder is loaded (`<input webkitdirectory>` or a dropped directory walked via `webkitGetAsEntry`). `folderFiles` maps root-relative paths to `File`s (`.git`/`node_modules` skipped; `folderLower` gives case-insensitive lookup); `currentDocPath` is the open document, and `#docSelect` lists the folder's markdown files. After each render, `assignHeadingIds()` gives every heading a GitHub-compatible slug, and `rewriteResources()` points relative `<img>` at blob URLs and sets external links to `target=_blank`. A delegated click handler on `#content` handles `#anchor` (scroll), relative `.md` (`openFolderDoc` + `history.pushState`; `popstate` restores), other relative files (blob URL in new tab), and shows a `toast()` when a target can't be resolved (or no folder is open).
- **Reload & live handles** — `File` objects from `<input type=file>` are snapshots (Chrome refuses to re-read them after the file changes), so open buttons and drop prefer the File System Access API (`showOpenFilePicker`, `showDirectoryPicker`, `DataTransferItem.getAsFileSystemHandle`) and fall back to inputs / `webkitGetAsEntry`. The source is tracked in `fileHandle` / `lastFile` / `dirHandle` (reset by `clearFolder()`); `folderFiles` values may be `File`s or `FileSystemFileHandle`s — always go through `getFolderFile(path)` / `blobUrlFor(path)` (both async). `reloadDoc()` (↻ icon button, shown via `body.has-doc`) re-reads from whichever source exists, re-walks a directory handle (`readDirHandle`) so added files appear, and restores scroll after `renderMarkdown`'s returned promise (settles when all diagrams are drawn).
- **Recent files & folders** — IndexedDB db `md-viewer`, store `recent` (keyPath `id`). Entries are `{kind: "file"|"folder"|"copy", name, handle, text, docPath, scrollY, openedAt}`: `file`/`folder` keep the `FileSystemHandle` (cloneable into IDB in Chrome/Edge; reopening goes through `ensureReadPermission` → `requestPermission`, which needs the click's user activation), `copy` keeps the text when there was no handle (≤5MB). `loadFile` / `openDirHandle` call `recordRecent` (dedupes via `isSameEntry` or name, caps at `RECENT_MAX`) or, when given a `recentEntry`, `resumeRecent` + restore its scroll/doc. `currentRecentId` (cleared by `clearFolder()`) is what `saveProgress()` (debounced, on scroll and folder navigation) updates. UI: `#recentSection` on the start screen and the `#recentMenu` dropdown, both filled by `fillRecentList`; `refreshRecentUi()` toggles `body.has-recent`. Webkitdirectory/`webkitGetAsEntry` folders have no handle and aren't recorded.
- **Real-time headless testing** — IndexedDB does real I/O while `--virtual-time-budget` races ahead, and `--dump-dom` ignores `--timeout`, so IDB-dependent tests need a real-time run: launch Chrome with `--remote-debugging-port=0 --user-data-dir=<abs path>`, read the port from `<profile>/DevToolsActivePort`, then drive it over the DevTools WebSocket (Node ≥22 has global `WebSocket`/`fetch`): `Page.navigate`, wait, `Runtime.evaluate` / `Page.captureScreenshot`. Reusing the profile across runs tests persistence. Don't kill `chrome.exe` by image name — filter by the profile path in the command line so the user's browser is untouched.
- **Headless folder-mode testing** — dispatch a synthetic `drop` event whose `dataTransfer.items[0].webkitGetAsEntry()` returns fake directory/file entry objects (in fake `readEntries`, mark the reader done *before* invoking the callback, since it's called synchronously). FileReader is slow under virtual time, so leave ~1.5s between steps.
